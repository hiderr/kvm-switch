# Проверка KVM Switch 1.1.3 на двух Mac

Автотесты: `python3 tests/run.py`. Они компилируют фактический `main.swift`, исключая
только запуск NSApplication, и используют перехват вывода событий вместо CGEvent.post.
Сетевые проверки используют настоящие TCP-соединения на loopback. Разрешения ОС и
физическую периферию эти тесты не проверяют.

## Установка пары

1. Получить SSH-доступ к обоим Mac и проверить имя устройства, пользователя и версию macOS.
2. Сохранить копию существующего `/Applications/KVM Switch.app` и
   `~/Library/Application Support/KVM Switch/config.json` на каждом Mac.
3. Передать одинаковые исходники 1.1.3, сверить SHA-256 `main.swift`, выполнить тесты
   и `./build.sh` на каждом Mac. Использовать существующий сертификат каждого Mac (при необходимости через
   `KVM_SIGNING_IDENTITY`); приватные ключи подписи между компьютерами не копировать.
4. Остановить старые приложения, поставить обе сборки в `/Applications`, запустить
   оба приложения. Старая и новая версии намеренно не передают ввод между собой.
5. Проверить Accessibility, Input Monitoring, Local Network, выбранного peer и
   зеркальное направление края. Сохранённые настройки не стирать.
6. Агент на втором Mac независимо фиксирует версию, SHA-256, состояние соединения
   и результаты приёма. При отсутствии удалённого агента не считать эту часть выполненной.

## Проверки с настоящим вводом

- Клавиатура/мышь подключены к Mac A: текст, оба Command/Shift/Option, клики, drag,
  скролл, переход через край, возврат хоткеем.
- Подключить устройства к Mac B и повторить без изменения ролей в приложении.
- Во время управления B воспользоваться его локальной клавиатурой/трекпадом:
  ввод остаётся на B, A прекращает удалённую передачу. Затем включить обратную передачу.
- Во время управления B с клавиатуры A несколько раз нажать Enter и ⌘V в редакторе,
  терминале и приложении, где наблюдался скачок. Повторить вставку через менеджер
  буфера обмена. При неподвижной мыши A должен оставаться в удалённом режиме,
  следующий ввод должен попадать на B. Повторить в обратном направлении.
- Программно созданные события на B и уведомления мыши с нулевыми delta не должны
  прекращать сессию. Физические нажатия и реальные движения на B по-прежнему
  возвращают управление; в debug.log появляется `local input: returning control`.
- Проверить ⌃⌥⌘Esc при активной передаче и после изменения обычного хоткея.
- Разорвать сеть при активной передаче. Следующее физическое событие после истечения
  1,5-секундного срока ответа должно пройти локально; таймер восстанавливает режим
  без нажатий, насколько позволяет планировщик ОС.
- Удерживать Command, Shift и кнопку мыши, затем разорвать связь. На работающем
  принимающем приложении не должно остаться нажатых через KVM клавиш/кнопок.
- Перезапустить каждый peer несколько раз: связь восстанавливается без цепочки
  взаимных перезапусков. Захват ввода самопроизвольно не включается.
- Изменить peer/порт во время передачи: локальный ввод сразу доступен.
- Сон/пробуждение и переподключение Wi-Fi: старые события не воспроизводятся как новая сессия.

## Проверка зависания

Перед SIGSTOP или искусственным зависанием главного потока запустить **независимый**
процесс с ограниченным временем, который пошлёт SIGCONT нужному PID. Он не должен
находиться внутри проверяемого процесса. Записать PID заранее и не останавливать
все процессы по совпадению части имени.

- Приостановить принимающий процесс, сохранив открытый TCP. На отправителе после
  истечения срока ответа события должны проходить локально.
- Приостановить отправитель: после отключения event tap системой его отдельный
  таймер не должен продолжать удерживать курсор (такого таймера в 1.1.1 нет); отдельный помощник должен показать курсор после истечения своей аренды.
- Возобновить процесс: требуется новое включение передачи, старую сессию продолжать нельзя.

Это план аппаратной проверки, а не утверждение о её выполнении. Поведение системного
event tap при недоступности зависит от macOS; никакая проверка приложения не даёт
гарантии работоспособности при зависании самой ОС.

Документация Apple: [отключение event tap](https://developer.apple.com/documentation/coregraphics/cgevent/tapenable(tap:enable:)),
[управление курсором](https://developer.apple.com/library/archive/documentation/GraphicsImaging/Conceptual/QuartzDisplayServicesConceptual/Articles/MouseCursor.html),
[отдельное состояние источника событий](https://developer.apple.com/documentation/coregraphics/cgeventsourcestateid).


## Проверка помощника курсора (1.1.1)

Реальный курсор должен скрываться после подтверждения helper и показываться при
нормальном возврате. Для отказов проверить отдельно остановку/завершение основного
процесса и остановку/завершение helper. У каждого процесса собственный PID;
сигналы посылаются только тестовым процессам с независимым возвратом SIGCONT.

На обеих машинах 21.09.2026 выполнено по 13 проверок фактической видимости курсора:
скрытие, SIGSTOP основного процесса, SIGKILL основного процесса, SIGSTOP helper,
SIGKILL helper и восстановление после каждой проверки. Для наблюдения использовался
C-вызов устаревшего `CGCursorIsVisible`; в продукт он не включён. Наблюдение после
show выполняется с учётом асинхронного обновления WindowServer. Полные локальные
отчёты лежат в `.context/cursor-process-results.json`, скрипты — в `.context` workspace.
Это подтверждает проверенные сценарии на текущей macOS, а не гарантию для будущих
версий WindowServer. Непрерывный перевод реальной мыши через край после установки
должен отдельно подтвердить пользователь.

## Клавиатура и задержки (1.1.2)

Полная матрица и границы проверки описаны в `KEYBOARD-VALIDATION.md`.
Прямой TCP echo-тест между Mac (1 500 записей, примерно 125/с) показал медиану
RTT 12,2 мс, p95 173,7 мс и максимум 224,1 мс. С интерактивным приоритетом:
12,6 / 176,3 / 236,2 мс соответственно. Этот замер не подтверждает улучшения
сетевой задержки. Прямой AWDL-прогон не установил связь; автоматический выбор
Bonjour в приложении сохранён.

Изолированная обработка 10 000 движений без CGEvent.post ускорилась с 368,7 до
2,6 мс после кеширования геометрии экранов. Это микротест затрат кода, а не
измерение задержки настоящего курсора. Во время передачи приложение запрашивает
точность таймеров/I/O; вне сессии освобождает запрос. Скачки Wi-Fi требуют
отдельного наблюдения с физической мышью после установки.

## Обработка пачек движений (1.1.3)

1 042 регрессионные проверки прошли на каждом Mac. Добавлены проверки:
100 движений → одно обновление с тем же результатом; последовательное ограничение
по краям при движении туда-обратно; возврат через край; границы пачек перед
кликами/drag/клавишами/END/сменой модификаторов; отсутствие отложенного движения
после закрытия или истечения срока сессии. Независимый агент на втором Mac
проверил код и не нашёл блокирующих ошибок. Как прежде, вывод событий в тестах
подменён записью, поэтому реальная плавность требует пользовательской проверки.

Контрольные замеры до установки, по 1 500 пакетов: UDP при работающем KVM дал
RTT p95 197,2 мс и максимальный интервал получения 255,5 мс; с выключенным KVM —
183,6 и 245,3 мс. TCP дал p95 189,5 мс. UDP не терял пакеты и не менял их порядок.
Оба Mac показывали Wi-Fi 5 GHz, канал 56/160 MHz, уровень сигнала около −38/−39 dBm.
Задержки сохранялись без KVM; его очередь не объясняет все паузы.

После установки 1.1.3 проверка UDP с SO_TIMESTAMP/recvmsg подтвердила:
RTT p95 194,5 мс; после вычитания задержек обработки обоих процессов — 192,7 мс.
От поступления пакета в ядро до Python: p95 0,21 мс локально и 3,24 мс на втором
Mac. Максимальный интервал поступления в ядро — 259 мс. Из 1 470 запросов сервер
получил все; отправитель получил 1 458 ответов. Основные задержки находятся до
обработки пользовательским кодом. Тест не различает проблемы роутера, радио,
драйвера и сетевого стека. Thunderbolt Bridge на обоих Mac был inactive.

## Набор текста у края экрана (1.1.4)

21.09.2026 на обоих Mac прошли 1 064 регрессионные проверки. Новый тест на старой
логике воспроизводил возврат: 80 px к краю → Enter/⌘V → ещё 50 px. Теперь набор
текста сбрасывает накопление. Отдельно проверены сброс после паузы более 250 мс,
остановка/смена направления, сохранение переключения при непрерывном движении,
программные нажатия и уведомления мыши без движения.

`tests/Typing.swift` проверяет реальную передачу по LAN с включённым краем экрана:
по 20 циклов Enter/⌘V в каждом направлении, по 120 клавиатурных событий и 60
движений. Оба направления прошли; клавиши и модификаторы получены по порядку,
неожиданного возврата и оставшихся нажатых клавиш нет. Вывод подменён записью:
тест не устанавливает event tap и не вводит текст в открытые приложения.

Сборка пробника: `python3 tests/build_typing.py .context/typing-probe`.
На принимающем Mac: `.context/typing-probe receive <IP-второго-Mac> .context/typing-receive.json`.
На отправляющем: `.context/typing-probe send <IP-второго-Mac> .context/typing-send.json`.
Используется отдельный TCP-порт 53646; оба процесса завершаются автоматически.

Отчёты выполненного LAN-прогона сохранены в `.context/typing-{to,from}-peer-{local,remote}.json`.
При кратком наблюдении реального ввода пользователь сообщил, что скачок сейчас
не воспроизводится. Поэтому исходный аппаратный сценарий не считается подтверждённо
устранённым только по результатам автоматических проверок.

После установки 1.1.4 пользователь повторно включил разрешение Local Network на
обоих Mac. Приложения перезапущены; в 16:14:09 UTC оба журнала подтвердили
`application heartbeat ready` с противоположным Mac. На обоих сохранены
`capture=true accessibility=true`; установлена версия 1.1.4.

## Жесты трекпада (1.1.5)

Причина: маска event tap не включала CG type 29 (все мультитач-жесты), а запись
прокрутки передавала только целые точечные дельты без фаз и инерции. Пинч на общем
трекпаде срабатывал на управляющем Mac, а не на втором.

Исправление: события прокрутки (22) и жестов (29) передаются как сериализованный
`CGEvent` (`CGEventCreateData`) после 32-байтного заголовка; принимающий Mac
восстанавливает событие, проверяет совпадение типа, ставит его к своему курсору и
свежую метку времени. Записи других типов с полезной нагрузкой отбрасываются.
Кадры длиннее 32 байт старые версии не понимают — обновлять нужно оба Mac.

Проверки 22.09.2026: `NSEvent(cgEvent:)` подтверждает соответствие HID-типов
8/5/22/16/32 → magnify/rotate/smartMagnify/swipe/pressure и фаз IOHID 1/2/4 →
began/changed/ended. Сериализованные на этом Mac (macOS 26.6.2) pinch и прокрутка
с фазой декодировались на втором Mac (26.5.1) с теми же значениями. 1 080
регрессионных проверок прошли, включая доставку трёх фаз пинча и фазовой прокрутки
по TCP между двумя Node. Реальный жест на общем трекпаде после установки
подтверждается пользователем.
